# 需求规格 v0.1

需求来源：用户提供的 `讨论.txt` 与 2026-09-15 本轮指示。本文区分明确目标、建议方案和待确认参数；旧聊天中的举例不是候选人的事实档案。

## 1. 明确目标

- 服务中国境内求职，国内平台至少包含 BOSS 直聘、智联招聘，另一通道为外企招聘官网。
- 形成 JD 采集、LLM 匹配评分、中英文简历选择/定制、自动填表、投递记录的连续流程。
- 尽量复用现成 GitHub 项目，减少重复开发。
- 将需求与实施方案沉淀到 `xuebuhuiya/JobPilot-CN`。

## 2. 从聊天提取的产品需求

| ID | 需求 | 优先级 | 验收结果 |
|---|---|---|---|
| R01 | Master Profile 统一维护基本信息、工作教育经历、项目与证据 | P0 | 所有自动生成内容可回溯到已确认事实 ID |
| R02 | BOSS、智联岗位采集 | P0 | 至少各一条带完整 JD、来源链接、采集时间的样本 |
| R03 | 外企官网岗位采集 | P0 | 官网链接可导入，记录职位 ID、地点、招聘状态和申请链接 |
| R04 | 去重与硬条件筛选 | P0 | 相同来源岗位重复导入不新增；不确定条件进入待核实 |
| R05 | LLM 评分、原因与缺口说明 | P0 | 返回结构化分数、履历证据、JD 证据、风险和未知项 |
| R06 | 中英文、多方向简历选择 | P0 | 依据岗位语言和职责选择；可人工覆盖并保留版本 |
| R07 | 按 JD 定制简历 | P0 | 展示修改前后差异，不新增无事实支持的经历与数字 |
| R08 | 招呼语、开放题答案草稿 | P1 | 每项可编辑；没有事实依据的答案留空 |
| R09 | 外企 ATS 辅助填表和附件选择 | P1 | 展示已填、未填、附件和待审核项；不将填完视作提交成功 |
| R10 | 最终审核与提交 | P1 | 审核绑定岗位、简历版本、答案及动作；材料变化使旧审核失效 |
| R11 | 投递与跟进台账 | P0 | 保存尝试时间、渠道、材料版本、结果证据、状态；CSV 可导出 |
| R12 | 回复/面试/拒绝/Offer 跟进 | P2 | 手动更新先行；只有适配且可核实的渠道才自动监听 |

P0 表示第一阶段核心闭环；P1 表示第二阶段在线操作；P2 表示后续增强。

## 3. 岗位匹配规则（建议初始设计）

方向允许配置 AI 应用、ML、Agent/RAG、工业 AI、时序建模、CV、Research / Applied Scientist、Software。不把 AI 求职等同于图像算法，也不默认用户满足研究岗或校招资格。

先做资格筛选，再评分：工作地点、校招/社招身份、学历、经验、工作许可、薪资硬底线。只有明确冲突才淘汰；缺失信息标记 `needs_verification`，不得猜测或自动通过。

建议使用 0–100 分：技能 30、项目/职责 30、资历 20、领域 10、个人偏好 10。每维有解释和证据；这是一套拟开发的统一规则，不代表 BossHunter 现有算法。

| 分数 | 分类 |
|---|---|
| 85–100 | 重点评估 |
| 70–<85 | 普通评估 |
| 55–<70 | 观察 |
| 0–<55 | 默认隐藏，可恢复 |

分数不是录用概率，任何分档都不自动授权投递。阈值参考原聊天并消除了 8.5 等边界重叠，后续用本人判断的样本校准。

外包、招聘代理和偏销售岗位可设过滤规则，但应引用 JD 或公司信息依据；仅凭公司名称不能认定外包。外企身份和实际招聘主体分开记录。地点只有 Shanghai 时只能记上海，不能推断浦东。

## 4. 简历与问答

- 母库记录事实的来源、确认状态、适用时间和可公开范围。
- 首期建议准备中文 AI 应用、英文 AI/ML 两类模板；Software / Research 版本由实际经历和岗位决定。
- 简历语言优先按岗位要求，其次 JD 语言，不按“外企一定英文”机械判断。
- 定制允许重排、删减、翻译与基于已有事实改写；不得捏造学历、任职、论文、生产指标或工作许可。
- 保留个人与团队贡献、离线回放与真实生产结果的区别。
- 工资期望、到岗时间、签证/工作许可、背景调查与同意条款由本人明确提供，不能由模型猜测。
- 保存生成器版本、模板版本、事实 ID、PDF 文件哈希与修改差异。

## 5. 原聊天中需要纠正或重新核实的内容

1. Monash 硕士、Bilateral Brain Thesis、Android、ASP.NET 等是聊天举例，未核实，不写入个人 Profile。
2. Apple、Microsoft、Amazon 等公司和岗位链接是线索，不保证岗位仍开放，也不据此认定本人符合校招条件。本轮是系统选型，未重新验证这些职位的招聘状态。
3. BossHunter 对智联的支持不包含自动投递；第一版需手动提交并回填。完整智联自动填表属于后续待验证目标。
4. ApplyPilot/JobFill 支持部分 ATS，不代表覆盖所有中国外企官网。以实际申请 URL 和具体租户页面为准。
5. “17 类 ATS”是 Auto-Fill-Forms 作者文档声明，不能当作本站已经完成的兼容性测试。
6. 共享 Profile、统一评分、自动选择简历和统一台账不是两个项目下载后就具备的功能。

## 6. 操作边界与非功能需求

- Windows 本地单用户优先，浏览器会话单独存放，服务仅监听本机。
- 默认采集/准备模式；验证码、登录失效、频控和未知页面进入暂停状态，不自动重试提交。
- 初期采用逐岗位人工审核；BOSS 发招呼语和外企提交申请分别记录。
- 页面中的提示词不得覆盖系统规则；不得因 JD 内容自动执行命令或向新地址上传简历。
- 每次失败可定位到输入版本、步骤与证据。提交结果未知时先核对，不能直接重投。
- 原始 JD、个人资料和模型调用内容按必要范围处理。日志不含 Key、Cookie；个人数据不进入 Git。

## 7. 待确认参数（不阻塞本阶段文档与下载）

| 参数 | 当前处理 |
|---|---|
| 最新中英文简历与项目事实 | 留空，等待本人提供/指定 |
| 城市、薪资、工作经验、校招/社招资格 | 不继承上游示例值，不建立硬过滤 |
| 公司偏好与外包容忍度 | 作为可配置项，不自动写死 |
| LLM 服务商、模型与每日费用预算 | 配置化，Key 本地填写 |
| 首批外企名单与实际岗位链接 | 待建立，用真实页面决定 ATS 优先级 |
| 是否允许逐项审核后由工具执行提交 | 默认本人完成最终提交；后续明确配置 |

历史求职偏好只作为设计参考，不替代本轮参数确认。原聊天全文保留在仓库外，公开文档只保留产品需求。
