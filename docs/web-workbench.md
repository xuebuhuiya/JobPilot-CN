# JobPilot-CN 网页工作台 v0.2

## 打开

双击仓库中的 `start-jobpilot.cmd`，访问 http://127.0.0.1:8787 。Python 3.10+，仅标准库，无需安装前端依赖。

- `8787`：JobPilot-CN 自建岗位、审阅与沟通工作台。
- `8686`：BossHunter 的采集与模型配置页面，继续独立运行。
- `start-workbench.cmd` 仍启动 BossHunter；新入口是 `start-jobpilot.cmd`。

也可运行 `python workbench.py --port 8787`。关闭该前台进程即可停止服务；脚本后台启动的服务日志在 `data/runtime/jobpilot-*.log`。

## 已实现

1. 岗位列表：搜索、资格筛选、审阅筛选、原分排序、资格优先排序、已移除记录。
2. 详情：原始链接、完整JD、资格与质量阻断原因、上游评分依据。
3. 本人审阅：结论和必填备注持久保存；已硬排除或移除的岗位无法标为值得申请。
4. 沟通记录：公司、联系人、类型、发生时间、依据；具体岗位未知可先保存公司级记录，之后关联同公司岗位。
5. 正式申请状态：单独回填，需要本人确认依据；打招呼不自动变为已正式投递。
6. 操作记录：显示最近300条导入、审阅、申请变更与沟通关联事件。
7. 同步：读取本地BossHunter已保存岗位，重新应用JobPilot资格规则；不触发采集、模型调用、消息或投递。

网页目前不修改候选人配置；使用 `private/candidate-rules.json`。同步来源固定为启动时指定的本地库。简历库、JobFill对接、网页启动采集、自动跟进仍待后续实现。

## 数据边界

业务数据保存在 `data/jobpilot.db`。新增 `contacts` 表；原有岗位、快照、事件表保持兼容。沟通记录不会因同步丢失；来源岗位变更后按原规则重置审阅结论，保留申请状态。旧详情的保存携带岗位版本，已变化时拒绝保存并要求刷新。

页面只绑定127.0.0.1；使用Host校验、同源和随机令牌校验保护写入，限制请求大小。静态文件仅提供明确列出的HTML/CSS/JS，不提供private、data或源代码目录。JD和模型输出以纯文本显示，不作为HTML执行。此服务面向单机使用，不提供多用户登录或公网部署能力。

截图回填保留为公司级事实，不因同公司只有一个已采集职位就强行断言是该职位。发生日期若来自截图推定，须在备注中明确；已读不自动等于对方回复。真实截图和沟通信息只保存于Git忽略的data目录。
